1.  Project  Vision  
Aria  is  an  AI-powered  emotional  support  web  application  that  provides  therapy-style  
conversations
 
to
 
users
 
seeking
 
mental
 
health
 
support.
 
The
 
system
 
is
 
designed
 
to
 
feel
 
as
 
close
 
to
 
a
 
human
 
therapist
 
as
 
possible
 
—
 
warm,
 
unhurried,
 
deeply
 
remembering,
 
and
 
grounded
 
in
 
real
 
clinical
 
techniques.
  
What  Makes  Aria  Different  
Ordinary  chatbot Aria Forgets  everything  after  session  ends  Remembers  across  months  of  sessions  Generic  empathetic  responses  Grounded  in  CBT,  DBT,  ACT  via  live  RAG  retrieval  No  safety  system  Crisis  detection  with  hardcoded  emergency  responses  Asks  multiple  questions  at  once  One  question  per  response  —  like  a  real  therapist  No  data  protection  Field-level  encryption,  DPDP  Act  2023  compliant  Cold  restarts  every  session  Callbacks  to  previous  sessions  by  name   
Core  Philosophy  
Design  Principle 80%  of  the  quality  difference  between  a  mediocre  and  excellent  AI  therapist  lives  in  three  things:  the  system  prompt,  the  memory  architecture,  and  the  RAG  knowledge  base  —  not  which  model  you  use  or  whether  you  trained  it  yourself.   
Non-Negotiable  Boundary Aria  is  an  emotional  support  tool,  not  a  licensed  therapist.  It  must  never  diagnose,  never  prescribe,  and  must  always  recommend  professional  help.  The  safety  layer  is  built  first,  before  any  other  feature.

3.  Safety  Architecture  (Build  This  First)  
Critical  Rule The  safety  layer  is  built  before  any  other  feature.  Not  after  the  UI,  not  after  authentication  —  first.  An  AI  that  handles  mental  health  content  without  a  robust  safety  system  can  cause  real  harm.   
Crisis  Detection  Pipeline  Every  user  message  passes  through  a  crisis  classifier  before  reaching  the  main  LLM.  This  runs  
on
 
claude-haiku
 
(fast,
 
cheap)
 
and
 
scans
 
for
 
suicidal
 
ideation,
 
self-harm,
 
and
 
acute
 
distress.

The  5  Techniques  That  Create  Human  Feel  
# Technique What  it  is Example 1  Reflective  listening  Paraphrase  before  responding  "It  sounds  like  you're  feeling  overwhelmed  by  work  —  is  that  right?"  2  One  question  only  Never  ask  two  questions  "What  does  that  feel  like  for  you?"  —  not  two  questions  at  once  3  Tentative  emotion  naming

6.  RAG  Knowledge  Base  —  Therapy  Books  in  the  
Prompt
 
RAG  (Retrieval  Augmented  Generation)  is  how  Aria  uses  real  clinical  knowledge  without  
fine-tuning.
 
Therapy
 
resources
 
are
 
chunked,
 
embedded,
 
stored
 
in
 
a
 
vector
 
database,
 
and
 
the
 
most
 
relevant
 
passages
 
are
 
retrieved
 
and
 
injected
 
into
 
every
 
prompt.
  
Why  RAG  —  Not  Fine-Tuning  
Important The  model  already  knows  every  major  therapy  framework  from  its  training.  Fine-tuning  it  on  books  adds  noise,  not  knowledge  —  like  re-teaching  a  doctor  their  curriculum.  RAG  retrieves  the  right  passage  at  the  right  moment,  live,  for  free.   
The  RAG  Pipeline  —  Step  by  Step  1.  Read  therapy  resource  files  (PDF,  TXT)  2.  Chunk  into  concept-sized  pieces  (~600  characters,  ~150  words,  one  technique  per  
chunk)
 3.  Embed  each  chunk  using  OpenAI  embeddings  API  —  each  chunk  becomes  a  vector  4.  Store  vectors  +  metadata  (source,  modality,  chapter)  in  Qdrant  5.  On  every  user  message:  embed  the  message,  find  top  3  most  similar  chunks  6.  Inject  retrieved  chunks  into  system  prompt  as  'relevant  clinical  context'  7.  Model  responds  using  real  published  techniques  —  grounded,  accurate,  evidence-based

7.  User  Experience  &  Interface  Design  
The  interface  must  feel  like  walking  into  a  therapist's  office,  not  opening  a  chat  app.  Every  
design
 
decision
 
reinforces
 
calm,
 
safety,
 
and
 
trust.
  
Design  Principles  •  Calm  by  design  —  soft  neutrals  (warm  whites,  sage  greens,  muted  blues),  no  aggressive  
CTAs
 •  No  animations  faster  than  300ms  —  fast  motion  feels  anxious  •  Generous  whitespace  —  breathing  room  is  not  wasted  space  •  Typography  that  breathes  —  1.7  line-height,  readable  font  sizes  •  No  notification  dots,  badges,  or  dark  patterns  •  Crisis  button  always  visible  —  small,  persistent,  never  hidden   
Onboarding  Flow  —  5  Questions  Onboarding  is  a  conversation,  not  a  form.  Each  question  is  shown  one  at  a  time,  full  screen.   8.  "What's  your  name?"  —  personalisation  starts  immediately  9.  "What  brings  you  here  today?"  —  open  text,  sets  first  session  context  10.  "What  kind  of  support  are  you  looking  for?"  —  three  choices:  practical  tools  /  just  want  to  
be
 
heard
 
/
 
understand
 
myself
 
better
 11.  "Have  you  spoken  to  a  therapist  before?"  —  calibrates  how  much  to  explain  12.  "Are  you  currently  having  thoughts  of  harming  yourself?"  —  crisis  safety  check  with  clear  
hotlines

yes
  
Session  Interface  Features  •  Typing  indicator  that  is  slow  (2-3  seconds)  —  mimics  a  human  thinking  and  composing  •  Response  arrives  in  chunks  via  streaming  —  appears  like  someone  typing  in  real  time  •  Mood  check-in  slider  (1-10)  at  session  start  and  end  •  Optional  session  timer  —  like  a  real  50-minute  therapy  session  •  End-of-session  summary  card  —  themes  covered,  reflection  to  sit  with,  what  to  pick  up

 •  Breathing  exercise  widget  —  accessible  at  any  point,  animated  4-7-8  breathing  guide  •  Session  history  panel  —  past  sessions  visible,  content  encrypted  and  private

8.  Security,  Privacy  &  Legal  Compliance  
Why  This  Matters  Here  More  Than  Any  Other  App Therapy  conversations  contain  the  most  sensitive  data  a  person  can  share  —  family  trauma,  mental  illness,  relationship  failures.  A  breach  is  not  just  a  privacy  violation  —  it  can  destroy  lives.  Security  is  a  moral  obligation,  not  a  feature.   
Minimum  Security  Requirements  •  All  session  messages  encrypted  at  rest  —  MongoDB  field-level  encryption  (AES-256)  •  JWT  access  tokens  expire  in  15  minutes  •  Refresh  tokens  rotate  on  every  use  —  stored  as  httpOnly  cookie,  invisible  to  JavaScript  •  No  session  content  in  server  logs  —  log  metadata  only  (session  ID,  timestamp,  duration)  •  "Delete  my  account"  truly  deletes  everything  —  User,  Sessions,  Memory,  all  Qdrant  
vectors
 •  Auto-delete  inactive  accounts  after  12  months  •  Rate  limiting  on  all  API  routes  —  Redis  sliding  window,  60  requests/minute  per  IP  •  All  dependencies  audited  with  npm  audit  before  deployment

What  to  Say  When  Starting  Each  File   
For  the  crisis  detector Build  a  crisis  detection  service  for  a  mental  health  app.  It  must:  (1)  scan  every  user  message  for  crisis  keywords  before  the  message  reaches  the  LLM,  (2)  return  a  hardcoded  (never  LLM-generated)  crisis  response  with  Indian  helpline  numbers  when  triggered,  (3)  be  a  pure  function  with  no  side  effects.  Use  TypeScript.   
For  the  context  builder Build  a  context  assembler  for  an  AI  therapist  app.  It  takes  a  userId  and  sessionId,  queries  MongoDB  for:  (1)  last  12  session  messages,  (2)  the  rolling  session  summary,  (3)  the  user's

For  the  RAG  retriever Build  a  RAG  retrieval  function  that  takes  a  user  message  string,  embeds  it  using  the  OpenAI  embeddings  API,  queries  a  Qdrant  vector  collection  called  'therapy_knowledge',  and  returns  the  top  3  most  similar  chunks  with  their  source  metadata.  Use  TypeScript  and  the  Qdrant  JS  client.   
For  the  streaming  chat  endpoint Build  a  Next.js  14  App  Router  API  route  at  /api/chat  that:  (1)  authenticates  the  user  via  NextAuth  session,  (2)  runs  the  crisis  detector,  (3)  builds  the  context  using  the  3-tier  memory  system,  (4)  calls  the  Anthropic  Claude  API  with  streaming  enabled,  (5)  returns  a  ReadableStream  to  the  client.  Include  error  handling.   
General  Rules  for  Your  AI  Assistant  •  Always  use  TypeScript  —  never  plain  JavaScript  •  Always  handle  errors  with  try/catch  and  meaningful  error  messages  •  Never  hardcode  API  keys  —  always  use  process.env  •  Always  validate  user  input  before  processing  •  Never  log  message  content  —  only  log  session  IDs  and  timestamps  •  Use  async/await,  never  callbacks  •  Every  function  that  touches  the  LLM  must  have  a  timeout
